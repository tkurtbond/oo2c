# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## What this is

OOC / **oo2c** 2.1.x: an optimizing Oberon-2 compiler that translates
Oberon-2 into GNU C (it relies on gcc extensions such as statement
expressions `({ ... })`, `typeof`, and **nested functions**), plus its
standard library and tools (`oob`, `ooef`, `oowhereis`). Upstream
development stopped around 2011; this fork tries to make it build and run on
modern Linux (current target: Fedora 44, gcc 16, glibc 2.4x, Boehm gc 8.2,
libtool 2.5, autoconf 2.72). See `PLAN.md` for the porting plan and its
current status.

## How the build works (important)

oo2c is written in Oberon-2, so **it cannot be built from this git tree
alone**. Building needs an existing oo2c ("bootstrap compiler"):

- Release tarballs (`oo2c_64-2.1.11.tar.bz2` on SourceForge, project `ooc`)
  contain a `stage0/` directory of pre-generated C sources plus
  `stage0/Makefile.ext`. The top-level `Makefile` builds `stage0/oo2c` from
  them, then uses it to build `lib/obj/liboo2c.la` and `bin/oo2c`.
- `stage0/` is **not** in git (see `.gitignore`). In a git checkout you must
  pass `BOOTSTRAP_COMPILER=<path to a working oo2c>` to `make`, following
  "Build and Install Using a CVS Working Copy" in `INSTALL`:

  ```sh
  ./configure --prefix=$PREFIX
  . ./ENV                                   # sets OOC_DEV_ROOT, MAIN_MAKEFILE
  make "$OOC_DEV_ROOT/oo2crc-install.xml"
  $BOOT/bin/oo2c -M --config oo2crc-install.xml oo2c   # -> bin/oo2c from HEAD
  make install BOOTSTRAP_COMPILER=bin/oo2c
  ```
- `make dist` regenerates `stage0/` C sources from the current tree.
- The compiler reads its settings (cc, cflags, libtool, xsltproc, pragmas)
  from `rsrc/OOC/oo2crc.xml` / `oo2crc-install.xml`, which configure and
  make generate from `rsrc/OOC/oo2crc.xml.mk.in`. C compiler flags that
  configure picked up end up there, so they apply to *every* program oo2c
  later compiles, not only to the bootstrap.
- Build outputs (`sym/`, `obj/`, `bin/`, `lib/sym`, `lib/obj`, `stage0/`,
  generated config files) are git-ignored. `make distclean` removes them.

## Tests

`make test` (needs GNU tar and perl) runs the suites listed in
`TEST_SUBDIRS` in `Makefile`. Output goes to `test-output/`. Run the
pthreads check with `src/TestThread.Mod` only when built with
`--enable-threads=pthreads`.
`make test-hostess-ooc1 HOSTESS=<dir>` runs the external hostess test
cases (`<dir>` holds `testcases.dtd` and `oberon/`; see `PLAN.md`).

## Conventions for changes

- Oberon-2 sources: keep the existing style (2-space indent, `(* *)`
  comments, `(**` doc comments `**)` with `@oparam{}` markup). Module
  `X:Y:Z` lives in `src/X/Y/Z.Mod` or `lib/src/X/Y/Z.Mod`.
- When fixing a problem in generated C, fix the **generator**
  (`src/OOC/C/*.Mod`, `src/OOC/Make/TranslateToC.Mod`, the runtime headers
  in `lib/src/`), not the generated output. Hand-written `lib/src/**/*.c`
  files may be edited directly.
- A change to the compiler only takes effect after a rebuild with a
  compiler that can compile it. Bootstrapping order matters: if a change
  needs a newer compiler feature, say so in the commit message (as
  upstream did).
- Keep portability changes in `configure.ac`/`aclocal.m4` and regenerate
  `configure` and `lib/src/__config.h.in` with `autoconf -Wall` and
  `autoheader -Wall` (not `autoreconf`: `aclocal.m4` is hand-written and
  `aclocal` would overwrite it); remove `autom4te.cache` afterwards, and
  commit the regenerated files together with the inputs.
- Prefer targeted fixes over blanket warning suppression; when a
  `-Wno-error=...` or `-std=gnu17` style workaround is used, note it in
  `PLAN.md` so it can be revisited.
- Record what you learned about the port (new failure modes, workarounds,
  status of each phase) in `PLAN.md`.
- Don't commit downloaded tarballs, build trees, or test output. Unpack the
  bootstrap tarball outside the repo.
- Commit only when asked to.

## Known hazards on modern toolchains

- gcc ≥ 14 turns `-Wimplicit-function-declaration`, `-Wint-conversion`,
  `-Wincompatible-pointer-types` and `-Wreturn-mismatch` into errors.
  Known instance: compilers built before the `modern-linux` branch
  (including the 2.1.11 tarball) write a program main file without a
  prototype for `OOC_<Module>_open`, so bootstrapping with one needs
  `-Wno-error=implicit-function-declaration`.
  `src/OOC/Make/WriteMainFileC.Mod` now emits the prototype, and a
  compiler built from this branch compiles itself and the library
  with no gcc warnings.
- Compilers built from sources before the `modern-linux` branch
  (including the 2.1.11 tarball) call libtool with `--tag=CXX`; with
  libtool 2.x this drops `-lm` from `liboo2c.la` and linking `oo2c` fails.
  `src/OOC/Config/CCompiler.Mod` now uses `--tag=CC`; for the tarball,
  patch its `stage0/obj/OOC/Config/CCompiler.[cd]` (see `PLAN.md`).
- gcc ≥ 15 defaults to `-std=gnu23` (`bool`/`true`/`false` are keywords,
  `()` means `(void)`).
- Generated code uses GCC nested functions for local procedures, so
  clang can't be the C compiler; it must be gcc. Taking a nested
  function's address would need a trampoline, i.e. an executable
  stack. That only happens when a local procedure is used as a
  procedure value, which the Oberon-2 report forbids, and
  `src/OOC/IR.Mod` now rejects it (error 81, tests
  `tests/ssa` `procvar8`/`procvar9`). Don't loosen that check, and
  don't link with `-z execstack`.
- Oberon `CHAR` is C `unsigned char`, so an `INTERFACE "C"` module
  can't declare a libc function that takes `char*` under its own name
  without a gcc `-Wbuiltin-declaration-mismatch` warning. Use a link
  name plus a small C wrapper (see `lib/src/libc.Mod` / `libc.c`).
- The generated C type-puns through casted lvalues, so `configure` adds
  `-fno-strict-aliasing` to `CFLAGS` for gcc; keep it.
- Every generated `.c` file starts with `#pragma GCC diagnostic ignored`
  for `-Wunused-label`, `-Wunused-but-set-variable` and
  `-Wunused-parameter` (written by `TranslateToC.WriteCodeFile`), so a
  change there changes all of `tests/ssa-c-output/ref64/obj`.
- With `--enable-threads=pthreads`, gc ≥ 7 needs `GC_THREADS` (not the
  old `GC_PTHREADS`) defined before `gc.h`, or thread stacks are not
  scanned and the heap gets corrupted; `configure` defines it in
  `__config.h`.
- `LONGINT` is 32 bits and `HUGEINT` 64 bits; the 64-bit address type is
  selected via `ooc_target_address_type`. Watch for pointer/int truncation.
